# AML GNN для SAML-D

Проект на PyTorch для выявления подозрительных переводов в синтетическом наборе SAML-D. Модель оценивает отдельную транзакцию по её атрибутам и предшествующей истории взаимодействий отправителя, получателя и их контрагентов.

Данные (SAML-D) и их описание: https://github.com/BOztasUK/Anti_Money_Laundering_Transaction_Data_SAML-D

## Как работает модель

- Узлы графа — банковские счета, направленные рёбра — переводы.
- Целевая метка — `Is_laundering`. Поле `Laundering_type` исключено из признаков.
- Признаки перевода: сумма, время, валюты, местоположения банков и тип платежа.
- GNN агрегирует сообщения от исторических контрагентов, раздельно учитывая входящие и исходящие операции.
- В контекст попадают только операции строго раньше оцениваемого события. Переводы с одинаковым временем не используют друг друга.
- Результат — оценка риска и сигнал по порогу, выбранному на validation.

Message passing реализован непосредственно на PyTorch; PyTorch Geometric не требуется. Идентификаторы счетов используются для адресации графа, поэтому модель может обрабатывать новые счета без добавления обучаемых embeddings аккаунтов.

## Структура

```text
aml_gnn/
├── prepare.py       # Проверка CSV, признаки, временное разбиение и индексы графа
├── graph.py         # Выбор исторических соседей и сбор батчей
├── model.py         # Кодирование переводов и графовая нейросеть
├── run.py           # Обучение, оценка и применение
├── data/            # Исходные CSV; скачиваются отдельно
└── artifacts/       # Подготовленные массивы, checkpoints и результаты
```

## Установка

Рекомендуется Python 3.12 или новее.

```bash
python -m venv .venv
```

Активация в Linux/macOS:

```bash
source .venv/bin/activate
```

Активация в Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Установка зависимостей:

```bash
python -m pip install torch numpy pandas scikit-learn
python -m pip freeze > requirements-lock.txt
```

Для CUDA используйте подходящую сборку PyTorch с https://pytorch.org/get-started/locally/.

## Данные

Скачайте SAML-D по ссылке из авторского репозитория и поместите CSV в `data/SAML-D.csv`.

Обязательные входные столбцы:

```text
Date, Time, Amount, Sender_account, Receiver_account,
Payment_currency, Received_currency, Sender_bank_location,
Receiver_bank_location, Payment_type
```

Для обучения дополнительно нужен `Is_laundering` со значениями `0` и `1`. Формат даты и времени по умолчанию — `%Y-%m-%d %H:%M:%S`. Его можно изменить через `prepare.py --time-format`.

## Обучение и оценка

Команды выполняются из корня проекта. Директории подготовки и обучения должны быть пустыми или ещё не существовать.

### 1. Подготовка

```bash
python prepare.py --csv data/SAML-D.csv --out artifacts/dataset
```

Данные сортируются по времени и разделяются по наблюдаемым дням: приблизительно 70% / 15% / 15% на train, validation и test. Словари категорий и параметры нормировки вычисляются только на train. Неизвестные категории получают индекс `0`.

Результат: массивы `.npy`, индексы входящих и исходящих операций, `accounts.csv`, `preprocess.json` и `manifest.json`. Проверьте число строк и положительных случаев в каждой части по `manifest.json`.

### 2. Обучение

```bash
python run.py train --data artifacts/dataset --out artifacts/gnn --epochs 10 --batch-size 256 --depth 2 --fanout 4 --alert-rate 0.001
```

Основные параметры:

| Параметр | Значение |
|---|---|
| `--depth` | Число уровней message passing: 0, 1 или 2 |
| `--fanout` | Максимальное число исторических операций каждого направления на узел и уровень |
| `--batch-size` | Число классифицируемых переводов в батче |
| `--alert-rate` | Доля validation-оценок, используемая для выбора порога |
| `--pos-weight` | Вес положительного класса; по умолчанию отношение числа отрицательных примеров к положительным в train |
| `--device` | `cpu` или `cuda`; по умолчанию CUDA при доступности |

Лучшая модель выбирается по validation Average Precision (AP). Итоговый `artifacts/gnn/model.pt` содержит веса, архитектуру, параметры сэмплирования, кодировщики и порог. `best_unfinalized.pt` — промежуточное сохранение без окончательного порога; оно не предназначено для обычного скоринга.

### 3. Оценка на test

```bash
python run.py evaluate --data artifacts/dataset --checkpoint artifacts/gnn/model.pt --out artifacts/test
```

Результаты:

- `test_metrics.json` — AP, ROC-AUC, precision, recall, F1, число сигналов и ошибок, метрики дневного бюджета проверок;
- `predictions.csv` — оценки переводов, сигналы и истинные метки;
- `pr_curve.npz` — данные precision-recall кривой.

Архитектуру и порог настраивайте на validation. Test используйте для финальной оценки.

## Применение к новым переводам

Подготовьте CSV с уже наблюдавшейся историей и последующий пакет переводов. Метки для применения не нужны и не читаются.

```bash
python prepare.py --csv data/new_transactions.csv --history data/history.csv --encoder artifacts/gnn/preprocess.json --out artifacts/new_batch
python run.py score --data artifacts/new_batch --checkpoint artifacts/gnn/model.pt --out artifacts/new_predictions
```

Итоговый файл — `artifacts/new_predictions/predictions.csv`. Поле `row_id` — номер строки входного CSV с нуля; `risk_score` — sigmoid оценки модели; `alert` — результат применения сохранённого порога.

Более ранние события нового пакета становятся историей для более поздних. Поэтому пакет должен содержать наблюдавшиеся переводы. Для скоринга гипотетических неисполненных платежей требуется другая политика обновления контекста. История и новый пакет не должны дублировать операции.

## Проверка пользы графа

Обучите контрольный вариант без message passing на том же разбиении:

```bash
python run.py train --data artifacts/dataset --out artifacts/no_graph --depth 0 --epochs 10 --alert-rate 0.001
```

Он использует признаки перевода и причинные статистики двух счетов. Сравнение с `depth=1` и `depth=2` на validation показывает, улучшает ли качество информация от контрагентов.

## Ограничения и статус

- Подготовка загружает и сортирует CSV в памяти; полный SAML-D требует значительного объёма RAM. Обучение использует батчи и массивы с memory mapping.
- На каждом уровне выбираются последние `fanout` входящих и исходящих операций. Длинные цепочки и более старая история могут не попасть в окрестность.
- История должна быть своевременно доступной, а все входные поля — известны в момент оценки. Для скоринга до исполнения это необходимо проверить отдельно.
- `risk_score` не является откалиброванной вероятностью. Качество на синтетических данных не подтверждает качество на реальных переводах.
- Точный дневной top-K — оценка очереди после завершения дня; он отличается от применения фиксированного порога в потоке.
- Реализация предусматривает пакетную обработку. Потоковый сервис, инкрементальный индекс и обработка запоздавших событий в неё не входят.
- Веса, данные и подтверждённые метрики обучения не поставляются: результат необходимо измерить на скачанной версии SAML-D.

Перед запуском проверьте исправления в `graph.py`: в `batch()` должно быть присваивание `nodes = np.stack(...)`, ключ признаков дерева должен называться `x`, а после объединения масок нужно использовать одну переменную `mask = np.concatenate(selected_masks, axis=1)` во всех последующих операциях. В присланном варианте имя `masks` при дальнейшем обращении к `mask` приводит к несовпадению форм при `depth > 0`.
